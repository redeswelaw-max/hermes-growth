## What This Project Is

This is **Hermes Agent v0.14.0** (by Nous Research) deployed on Railway as a Telegram growth-marketing bot powered by **Kimi K2.6**.

**Key facts:**
- The repo contains the FULL Hermes Agent source code — do not delete core files
- 42 growth-marketing skills live in `optional-skills/growth-marketing/`
- Kimi provider lives in `plugins/model-providers/kimi-coding/`
- Frontends are **pre-built locally** and committed — do not rebuild in Docker
- Deploy target: Railway (`disciplined-eagerness` project)

---

## Golden Rules

### 1. NEVER delete `hermes_cli/web_dist/` or `ui-tui/dist/`

These are pre-built frontend assets. The Dockerfile does NOT run `npm install` or `npm run build`. If you delete these, the deployed app will crash or serve broken UI.

### 2. NEVER run `git clone` in the Dockerfile

The Dockerfile already copies the full repo (`COPY . .`). Do not add `git clone` commands — they will fail or bloat the build.

### 3. NEVER add Node.js to the Dockerfile

Node.js is intentionally excluded to keep the build fast. If you need to update frontends:
1. Build locally (see `DEPLOYMENT.md`)
2. Commit the output
3. Push and deploy

### 4. NEVER add a `healthcheckPath` to `railway.toml`

Hermes gateway does not expose HTTP. It uses Telegram long-polling. Adding a healthcheck will cause the deploy to fail with timeout.

### 5. ALWAYS use `uv sync --frozen` in Dockerfile

Do not use `pip install`. Do not use `uv pip install`. The `uv.lock` file ensures reproducible, fast builds. Using `--frozen` skips resolution entirely.

### 6. Environment variables go in the Dockerfile

Railway does NOT inject `[deploy.env]` when using `builder = "dockerfile"`. All env vars must be `ENV` directives in the Dockerfile. See current examples.

### 7. Do NOT modify upstream Hermes files unnecessarily

If Hermes releases v0.15.0, we want clean merges. Keep modifications minimal and well-documented.

|---|---|
| `Dockerfile` | Env vars, dependencies, build steps |

## Files You Should NOT Edit

| File | Why |
|---|---|
| `uv.lock` | Auto-generated by `uv lock`. Only regenerate if updating deps. |
| `hermes_cli/web_dist/` | Auto-generated by `npm run build` in `web/`. Rebuild locally. |
| `ui-tui/dist/` | Auto-generated by `npm run build` in `ui-tui/`. Rebuild locally. |


## Common Tasks

### Add a new skill

```bash
mkdir optional-skills/growth-marketing/new-skill
cat > optional-skills/growth-marketing/new-skill/SKILL.md << 'EOF'
---
name: new-skill
description: What it does
version: 1.0.0
metadata:
  hermes:
    tags: [growth, marketing]
---

# New Skill

Instructions here...
EOF

git add optional-skills/growth-marketing/new-skill/
git commit -m "Add skill: new-skill"
git push origin main
RAILWAY_API_TOKEN=... railway up
```

### Update an environment variable

Edit `Dockerfile`, find the `ENV` line, change the value, commit, push, deploy.

### Update Hermes version

1. Check upstream release: https://github.com/NousResearch/hermes-agent/releases
2. Update `pyproject.toml` version
3. Run `uv lock` locally
4. Check if frontends changed — rebuild if needed
5. Test locally: `hermes gateway`
6. Commit and deploy

### Fix a failed deploy

1. Check logs: `railway logs <DEPLOYMENT_ID> -d --lines 100`
2. Identify error
3. Fix in repo
4. Commit, push, `railway up`
